## 5. Architecture decision

### Internal paths
**KEEP independent**

There is no evidence to merge the internal state machines.

### Operator-facing output
**MERGE semantically through a projection layer**

The operator should not see three competing readiness rows.

### Cross-path priority
Do **not** use enum numeric order.

Use operational urgency for the next decision.

## 6. Preregistered OPERATOR_READINESS_V1

This is a projection only. It does not alter any accepted internal path.

### Active set

A path is active when readiness != WAIT.

### No active path

Output:
- WAIT
- direction = NONE

### Active paths all same direction

Output the most operationally urgent readiness using:

1. CONFIRMED / current CONFIRMA
2. ARMED
3. PREP
4. ALIGNED
5. WAIT

Rationale:
- a fresh ARMADO/PREP must not be hidden by a stale same-direction ALIGNED state;
- a current CONFIRMA is the strongest immediate operator event.

The projection retains:
- all active source paths;
- all source opportunity kinds;
- paths contributing the selected readiness.

### Opposite active directions

Output:
- research status = CONFLICT
- direction = NONE
- actionable unified CONFIRMA = false

Do not choose a winner.

Raw path states/events remain auditable.

### Confirmation collapse

If multiple paths emit same-direction CONFIRMA on the **same bar**:
- emit one operator CONFIRMA;
- preserve all confirming sources.

### Near confirmations on different bars

Do **not** suppress/deduplicate merely because they occur within +/-3 bars.

BTC provided no evidence that such events should be merged.

### Frame-only disagreement

If context frames disagree but every relevant path is WAIT:
- keep operator readiness WAIT;
- retain context conflict only in telemetry.

### Strength

Strength arbitration is **not** defined in this block.

Each source path keeps its own strength telemetry until readiness arbitration is validated.
